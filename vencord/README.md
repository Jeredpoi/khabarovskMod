# khabarovskMod для Vencord

Порт плагина модерации с BetterDiscord на [Vencord](https://vencord.dev/).
Работает параллельно с основной версией — это отдельная сборка, а не замена.

## Установка

Vencord не умеет подгружать плагины файлом: userplugins попадают в клиент
только при сборке из исходников. Понадобятся Node.js, git и pnpm.

```bash
git clone https://github.com/Vendicated/Vencord
cd Vencord
pnpm install --frozen-lockfile

mkdir -p src/userplugins
cp -r /путь/к/khabarovskMod/vencord/khabarovskMod src/userplugins/

pnpm build
pnpm inject
```

После этого плагин появится в настройках Vencord под именем **khabarovskMod**.
При каждом обновлении плагина сборку нужно повторять.

## Чем отличается от версии для BetterDiscord

**Настройки стали нативными.** Панель на 1030 строк ручной вёрстки заменена
на `definePluginSettings` — Vencord рисует её сам, в стиле Discord. Заодно
исчезли настройки внешнего вида (цвета, отступы, скругления): они существовали
только чтобы оформить самодельную панель, а нативной не нужны.

**История нарушений по конкретному пользователю.** В BetterDiscord-версии
история была общим плоским списком, и увидеть прошлые наказания конкретного
человека можно было только глазами. Здесь она прямо в его контекстном меню,
со счётчиком: `История нарушений (3)`. От прошлых наказаний зависит выбор
следующей ступени, поэтому смотреть их логично в момент выдачи.

**Формы выбирают правило меню, а не диалогом.** Модальное окно с выпадающим
списком заменено вложенным подменю — на клик меньше.

**Хранилище.** Вместо файла `khabarovskMod.config.json` настройки лежат
в хранилище Vencord, история — в IndexedDB. Править конфиг текстовым
редактором больше нельзя: у плагинов Vencord нет прямого доступа к файлам.

**Команда копируется, а не вставляется в поле.** Vencord не даёт удобного
доступа к полю ввода, поэтому команды идут в буфер обмена — как это уже
работает для кнопки «Одобрить».

## Что осталось прежним

- Все 30 пунктов правил (2.1–2.21, 3.1–3.5, 4.1–4.4) с их наказаниями
- Тексты устного предупреждения, предупреждения и остальных наказаний
- Ссылка на канал правил через `{rulesChannel}`
- Шаблон формы наказания и все его переменные
- Копирование команды по кнопке «Одобрить» в канале форм
- Быстрый повтор недавних наказаний

## Настройки

| Настройка | Назначение |
|---|---|
| Ник модератора | Подставляется в формы как `{moderatorNick}` |
| ID канала с правилами | Ссылка в конце сообщения. Пусто — без ссылки |
| Тексты наказаний | Отдельно для устного, предупреждения и остальных |
| Команды | `/warn`, `/mute`, `/ban`, `/user`, `/punish`, очистка |
| Сроки | Время мута в минутах, бана в днях |
| Шаблон формы | Переменные: `{moderatorNick}`, `{userId}`, `{userTag}`, `{ruleId}`, `{punishment}`, `{dateIssued}`, `{dateEnd}` |
| Канал форм | Копирование команды по «Одобрить», ограничение по каналу, названия кнопок |
| Подтверждение | Спрашивать перед выдачей наказания |

## Состояние

Код проходит проверку компилятором TypeScript и 28 тестов на совпадение
текстов с BetterDiscord-версией. **В живом Discord не проверялся** — нужна
сборка Vencord и прогон на сервере.

Отдельно стоит проверить контекстные меню: `contextMenus` в Vencord получает
готовые элементы React, и точная форма пунктов может отличаться от того, что
ожидается в коде.
